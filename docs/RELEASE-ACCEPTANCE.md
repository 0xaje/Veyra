# Veyra release closeout — fixed scope

Snapshot: 25 October 2026. This is a finite acceptance list, not a new feature roadmap. Reopen implementation only for a reproducible defect or security issue. A passed automated check is not represented as an interactive extension-wallet or physical-phone check.

## Accepted product scope

Public address checking; genuine Walrus recipient recall; relevant Tatum historical observations; optional consented self-service assessment saving, receipt/recall and persistent browser history; optional wallet-authenticated private recipient relationships. Saved assessments are never recipient approvals. Signed public recipient-confirmation publication remains outside this enabled release and is disclosed as unavailable.

## Remaining device/wallet checks — do once

Use an actual phone and a supported Sui wallet. These checks require those surfaces; a desktop cloud browser screenshot is not their substitute. No extra Mainnet memory write or funds transfer is necessary.

1. Open the deployed main checker at the phone's default text size. In both themes, confirm full address/receipt wrapping, no horizontal page overflow, usable bottom navigation and hamburger open/close. Scroll through Save this check review without consenting to another write.
2. Open wallet sign-in, reject/cancel it, and confirm a useful error with no authenticated private data shown. Then connect the intended wallet normally and check that switching/disconnecting clears the old wallet's private view. Do not sign or execute a payment.
3. From an already saved browser collection, privately obtain the recovery code. Restore it on the second browser using the app's form. Confirm the saved receipt appears, the previous browser loses access after refresh, and the used code fails on another restore. Keep the newly available code private; never put it in recordings or chat. Do not clear the original cookie before keeping a recovery method.
4. Navigate using Tab/Shift+Tab/Enter/Space on desktop. Confirm visible focus and readable controls. For the phone, confirm the confirmation checkbox and buttons are comfortable to tap. Report exact device/browser and pass/fail; do not invent a failure state or intercept provider responses.

A missing wallet extension may be tested as missing-wallet UX, but it is not evidence of a real wallet rejection. A real network outage can be observed and documented; do not mock a successful provider or claim an unobserved outage.
